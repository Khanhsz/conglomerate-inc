# Spec M1.8 — Bản đồ 7 thành phố, đối thủ có hồ sơ ngẫu nhiên, ra / vào thị trường

Duyệt 2026-11-12. Kiến trúc: ADR-0003. Công thức: economic-model §2, §5, §9, §18, §20.

## 1. Nguyên tắc
- **`m1-default` giữ nguyên từng cent** ở mọi bước (test `regression.m1.test.ts`). Scenario này có một thành phố, đối thủ khai sẵn, không khai `competition`.
- Deterministic theo seed. Mọi lựa chọn ngẫu nhiên dùng `ctx.rng(stream)` với stream riêng (`rival:<n>`, `entry:<cityId>`).
- Đối thủ dùng đúng lệnh, sổ cái và luật của người chơi. Không có số liệu giả.
- Tham số nằm trong content; hằng cấu trúc ở `constants.ts`.

## 2. Content
```yaml
# scenario
cities:
  - id: riverton
    name: "Riverton"
    gridW: 7
    gridH: 6
    districtSizeKm: 2
    sameDistrictKm: 0.5
    districts:
      - { id: rv-c1, name: "C1", x: 3, y: 2, zone: central, pop: …, mix: {…}, rentMonthly: …, fitOutCost: … }
competition:                       # không khai = không sinh, không thay thế (m1-default)
  initial: { localPerCity: [2, 3], chains: [2, 3] }
  maxPerCity: 5
  exitAfterMonthsWithoutStores: 3
  entryDelayMonths: [1, 4]
  attractive: { margin: 0.25, months: 6 }
```
- `zone ∈ { budget, central, premium }`; YAML cũ không có `zone` thì mặc định `central`. `name` tùy chọn (mặc định là id viết hoa).
- `city:` (số ít) vẫn hợp lệ và tương đương `cities: [city]` với `id` = tên viết thường không dấu cách.
- Id thành phố và id địa điểm duy nhất toàn scenario; tọa độ duy nhất trong từng thành phố; lưới cho phép ô trống.
```yaml
# industry
rivalGenerator:
  tierWeights: { basic: 3, standard: 4, premium: 3 }
  tiers:
    basic:    { markup: [3.4, 3.9], wageRatio: [0.90, 1.05], marketingShare: [0.01, 0.03] }
    standard: { markup: [3.6, 4.1], wageRatio: [1.00, 1.15], marketingShare: [0.02, 0.05] }
    premium:  { markup: [3.8, 4.3], wageRatio: [1.10, 1.30], marketingShare: [0.04, 0.08] }
  chainReachWeights: { regional: 2, national: 1 }
  reachCities: { local: 1, regional: 3, national: 7 }
  capital:       { local: [40000000, 70000000], regional: [80000000, 140000000], national: [150000000, 250000000] }
  initialStores: { local: [1, 2], regional: [2, 3], national: [3, 4] }
  expansion: { maxPaybackMonths: [12, 30], cashMultiple: [1.5, 3.5] }
  patienceMonths: [2, 5]
  names: { prefixes: [...], suffixes: [...] }
```
Mọi giá trị trên là đề xuất ban đầu (#62), hiệu chỉnh ở bước cân bằng.

## 3. State
```ts
GameState.schemaVersion: 2
GameState.nextIds += { company: number }
GameState.market: { targetChains: number; cities: Record<CityId, { targetRivals: number; entryDueDay: number | null }> }   // cities rỗng khi không có competition
CompanyStatus += 'exited'
AiCompany += {
  profile: {
    source: 'personality' | 'generated'
    qualityTier, markup, wageRatio, marketingShareOfRevenue
    expansion: { rule: 'averageRoi' | 'marginalGain', minMonthlyRoi, cashMultiple, maxPaybackMonths }
    closeAfterNegativeMonths
    reach: 'local' | 'regional' | 'national'
    homeCityId
  }
  foundedDay: number
  storelessMonths: number           // số lần chốt tháng liên tiếp không có cửa hàng mở
}
AiCompany.personality: giữ cho công ty khai sẵn; công ty sinh ngẫu nhiên không có
companyIds vẫn sắp theo id: công ty mới (id `ai-000001`, `ai-000002`…) được chèn đúng vị trí
Event += competitorEntered { companyId, name, cityId, reach, qualityTier }
       | competitorExited  { companyId, name }
```
`SetChannelBudget.target` với kênh `city` là id thành phố.

## 4. Thứ tự tick (bổ sung spec M1.6 §4)
```
0. ngày đầu tháng: entrySystem (§20.3–20.4) → AI §9 → chính sách đầu tháng
…
9. monthClose: sau bước distress / bankrupt, cập nhật storelessMonths và xét rút lui (§20.2)
```
Đối thủ mới sinh ở bước 0 mở cửa hàng ban đầu ngay trong bước đó (cùng đường lệnh như `createGame`), nên có mặt từ ngày gia nhập.

## 5. Web
- **Ván mới:** chọn thành phố xuất phát và seed (mặc định ngẫu nhiên, tạo ở lớp web). Message `init { seed, scenario }`. URL `?scenario=m1-default|atlas`, `?seed=<số>`, `?city=<id>`.
- **Message mới:** `viewCity { cityId }`. Snapshot gồm `cities[]` (tổng hợp: tên, dân số, số cửa hàng của người chơi, số đối thủ có mặt) và `districts` của thành phố đang xem.
- **Bản đồ:** dải chọn thành phố; lưới địa điểm theo `x, y`, ô trống để trống; nhãn khu; chú thích chỉ gồm công ty có mặt.
- **Hồ sơ đối thủ:** tên, ngày gia nhập, thành phố nhà, thành phố có mặt, phong cách bằng lời, số cửa hàng, giá trung bình, thị phần, nhận biết, doanh thu tháng ước tính (làm tròn 2 chữ số có nghĩa từ doanh thu tháng gần nhất). Không gửi markup, tiền mặt, lợi nhuận sang UI.
- **Màu:** `colorIndex` gán cho công ty theo thứ tự thành lập, 8 màu đã kiểm bằng validator.

## 6. Balance
- `--scenario m1-default|atlas`; smoke chạy cả hai.
- Bot chọn thành phố xuất phát đầu tiên của scenario; các luật bot giữ nguyên.
- Bất biến mới (§13): hồ sơ hợp lệ; công ty `exited` không có cửa hàng mở; số đối thủ có mặt ở mỗi thành phố ≤ `maxPerCity` ngay sau `entrySystem`.

## 7. Bước và nghiệm thu
| Bước | Nội dung | Nghiệm thu |
|---|---|---|
| 1 | Tài liệu | Đã duyệt kế hoạch |
| 2 | Nền nhiều thành phố | Hồi quy M1 nguyên vẹn; fixture 2 thành phố: không với tới nhau, truyền miệng và ngân sách tách riêng |
| 3 | Scenario atlas + bản đồ + ván mới | YAML khớp script; 7 thành phố, 30–35 điểm, 3 khu; e2e đổi thành phố và mở cửa hàng |
| 4 | Hồ sơ đối thủ + mở rộng theo lãi biên | Cùng seed cho cùng đối thủ; đặc điểm trong dải; M1 nguyên vẹn |
| 5 | Rút lui / gia nhập | Đối thủ bị loại thì có đối thủ mới sau 1–4 tháng; không vượt `maxPerCity`; m1-default không sinh ai |
| 6 | Hồ sơ đối thủ trên UI, màu, sự kiện | Ảnh chụp 4 tổ hợp, quét tương phản và bề ngang |
| 7 | Cân bằng atlas | Mục tiêu do balance-analyst đề xuất, người dùng duyệt; balance-log |
